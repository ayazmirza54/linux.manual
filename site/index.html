Quick start

# Clone it and open the file: no server, no install
git clone https://github.com/ayazmirza54/linux.manual
xdg-open linux.manual/site/index.html

On macOS, use open in place of xdg-open. To skip the clone, use the hosted copy.

# Serve the site folder on http://localhost:8000
python3 serve.py

serve.py needs only Python's standard library, and -p sets another port.

# Regenerate site/data/ from the upstream corpus
git clone --depth 1 https://github.com/SimonSchubert/LinuxCommandLibrary /tmp/lcl
python3 build.py --source /tmp/lcl/assets

build.py parses the corpus's markdown into the search index and the 128 buckets.

1. Type a command

Press / and type. A command's name opens its page, and anything else searches.

2. One bucket loads

Each page lives in one of 128 files of about 160 KB, and the browser reads only that file.

3. Read the page

Examples come first, then the synopsis, parameters, description, history, install and see-also.

The prompt is also a small shell: guides git opens a walkthrough, theme amber changes the colours, random opens a page you didn't know existed and help lists the rest.

Guides

Why offline?

  • You often need a man page when the network is gone: on a broken router, an air-gapped box or a train.
  • A static site can't fetch() its data from a file:// URL, because the browser blocks the request as cross-origin.
  • Script tags were never bound by that rule, so each bucket is a script and loads the same from a server, a folder or a USB stick.
  • Opening a page costs one local read of about 160 KB, where the whole corpus is a 20 MB download.

The prompt is a shell

  • Type a command's name to open its page, or anything else to search names, taglines and examples.
  • Builtins do the rest: man, ls, search, guides, tips, random, history and help.
  • Every page has an address, such as #/man/tar, that you can bookmark or share.

Keyboard first

  • / focuses the prompt from anywhere, ↑ ↓ move through suggestions and ⏎ opens one.
  • Single keys jump around, and ? lists them all.

Runs from file://

  • There is no framework, no build tooling and no runtime dependency: it is vanilla JavaScript, two stylesheets and a Python build script.
  • The search index, 743 KB, loads up front, so search never waits on a request.
  • Page bodies are keyed into buckets by crc32(name) % 128, the same function in build.py and app.js.

Four themes

  • Phosphor, amber, ice and paper are token swaps, so t or theme ice changes the theme in place.
  • crt toggles a scanline overlay for the full terminal look.

FAQ

Where do the commands come from?

From the Linux Command Library by Simon Schubert, an open-source corpus of command pages, guides and tips. linux.manual is a reader for it, and build.py turns the corpus's markdown into the data files.

Does it need a server?

No. Open site/index.html from disk and everything works, search included. It also runs on any static host, and serve.py is there if you prefer localhost.

How big is it?

The page bodies are 20.3 MB, split across 128 buckets of about 160 KB each, and the search index is another 743 KB. Only the index loads up front.

Does it call out to anything?

No. There are no analytics, no CDN and no web-font requests, because the fonts and every page ship in the folder.
